<Warning title="Conditional validation">Drafts support only 480p and final videos only 1080p. When `draft_task_id` is set, you may only send `resolution`, `output_format`, `watermark`, and `callback_url`; sending `prompt`, media fields, `role`, `duration`, `aspect_ratio`, `seed`, `generate_audio`, or `web_search` returns a 400 error.</Warning>

## Workflow

Both stages use the same model ID, `seedance-2.5-draft`, and the same endpoint. Switch between the **Step 1** and **Step 3** request examples in the API panel to see each body.

<Steps>
  <Step title="Submit the 480p draft">
    Send a normal Seedance 2.5 request without `draft_task_id`: `prompt`, `image_urls` / `video_urls` / `audio_urls`, `duration` (4-30 seconds), `aspect_ratio`, `generate_audio`, and `output_format` (`mp4` or `mov`). `resolution` must be `480p` and is filled in when omitted. The response returns `data.task_id`.
  </Step>
  <Step title="Query the draft result">
    Poll `GET /v1/videos/status/{task_id}` until `data.status` is `completed`. `data.result` contains the draft video URL and `data.usage.cost` the charge. The `data.task_id` of this completed task is the **`draft_task_id`** for the next step.
  </Step>
  <Step title="Submit the 1080p final video">
    Send only `model`, `draft_task_id`, and optionally `resolution` (`1080p`, filled in when omitted) and `output_format`. The prompt, media, duration, aspect ratio, seed, and audio setting are reused from the draft automatically.
  </Step>
  <Step title="Query the final result">
    Poll the new task ID returned in Step 3 with the same status endpoint; `data.result` contains the 1080p video once `data.status` is `completed`.
  </Step>
</Steps>

## Billing

- **Draft**: the same as a normal 480p video; when reference videos are supplied, their total duration is added.
- **Final video**: draft duration × the 1080p rate. Input-video duration is not added again, even when the draft used video references.
- The same draft can create multiple final videos; each one is a separate, independently billed task. Failed tasks are fully refunded.

## Limits

- `draft_task_id` must be a completed draft created by the current user within the last 7 days. Use the platform `task_id`, never an upstream task ID.
- `duration=-1` is not supported.
- Draft and final tasks always run on the generation account that created the draft and never fall back to another channel. If that account is unavailable, the final request returns 503; retry later.
