        ## Task Status


        | Status | Description | Action |

        | --- | --- | --- |

        | `pending` | Task is waiting to be processed | Continue polling |

        | `processing` | Task is being processed | Continue polling |

        | `completed` | Task execution completed | Directly obtain results from
        the `result` array list |

        | `failed` | Task execution failed | Check `code` and `message` for
        details |

        | `cancelled` | Task has been cancelled | Task cancelled, exit without
        further processing |


        ## Polling Practice


        <AccordionGroup>


        <Accordion title="Recommended polling interval">
          - **Initial Polling (First 30 Seconds)**: Every 2–3 seconds  
          - **After 30 Seconds**: Every 5–10 seconds  
          - **After 2 Minutes**: Every 15–30 seconds

        ::: tip[]
          Use exponential backoff to reduce server load and API costs.
        :::


        </Accordion>



        <Accordion title="Use callbacks instead of polling">
          For production applications, we strongly recommend using the `callback_url` parameter when creating tasks:
        - **No polling required**: Your server automatically receives
        notifications

        - **Reduced API costs**: Eliminates continuous polling requests

        - **Better performance**: Instant notification upon task completion

        - **Lower latency**: No delay between task completion and notification


        The data received via the callback is consistent with the `data`
        returned by the current interface.

        </Accordion>



        <Accordion title="Process completed tasks">
          When `status` is `completed`: 
            
            1. Extract the data from the `result` array 
            2. Download the generated content immediately 
            3. Store the content in your own storage 
            
            **⚠️Note**: The generated content URL usually expires after 24 hours.
        </Accordion>


        </AccordionGroup>


        ## Example: Complete polling process



        ```javascript Node.js


        async function pollTaskStatus(taskId, maxAttempts = 60, interval = 5000)

        {

        for (let attempt = 0; attempt < maxAttempts; attempt++) {

        const response = await fetch(
          `https://api.apipod.ai/v1/videso/status/${taskId}`,
          {
            headers: { 'Authorization': 'Bearer YOUR_APIPOD_API_KEY' }
          }
        );


        const res = await response.json();

        const { status, result, error } = res.data;


        console.log(`try ${attempt + 1}: status = ${status}`);


        if (state === 'completed') {
          console.log('✅ status completed!');
          console.log('result:', result);
          return result;
        }


        if (state === 'failed') {
          console.error('❌ task failed:', error);
          throw new Error(error);
        }


        // processing, waiting next polling

        await new Promise(resolve => setTimeout(resolve, interval));

        }


        throw new Error('task timeout');

        }



        // how to use


        try {

        const result = await pollTaskStatus('task_12345678');

        console.log('generate videos urls:', result);

        } catch (error) {

        console.error('error:', error.message);

        }
        ```
